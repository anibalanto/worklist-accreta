# Error de clasificación: cambiar la ruta o el tipo de retorno de un endpoint se reporta como capture roto

Un capture hecho con `--as spring-controller` **detecta** los dos cambios que el modo existe para detectar, y los **clasifica al revés**: sale `UNRESOLVED`, cuyo fix prescripto es `recapture` o `remove`. Lo que pasó no es que el ancla se haya perdido: es que el proveedor cambió el contrato.

Medido sobre `UserPublicController.java` de `hsi` —el caso de [`1d`](1d.task.md)— con el método `fetchPermissionsFromToken` capturado como `spring-controller`:

| Mutación en el proveedor | Estado | Debería |
|---|---|---|
| cuerpo del método: un log más | `OK` | `OK` ✓ |
| cuerpo: `collect(toList())` → `toList()` | `OK` | `OK` ✓ |
| un método nuevo arriba del ancla | `OK` | `OK` ✓ |
| un campo nuevo en la clase | `OK` | `OK` ✓ |
| renombrar el método | `OK` | `OK` ✓ |
| **tipo de retorno `List<Dto>` → `Dto`** | **`UNRESOLVED`** | `ALTERED` |
| **ruta del método `/permissions` → `/perms`** | **`UNRESOLVED`** | `ALTERED` |
| ruta de clase `/public-api/user` → `/api/user` | `ALTERED` | `ALTERED` ✓ |
| parámetro `user-token` → `auth-token` | `ALTERED` | `ALTERED` ✓ |

## La query pinnea lo que tendría que vigilar

```
(class_declaration
  (modifiers
    (annotation
      name: (identifier) @n0 (#eq? @n0 "RequestMapping")) @target)
  body: (class_body
    (method_declaration
      (modifiers
        (annotation
          name: (identifier) @n1 (#eq? @n1 "GetMapping")
          arguments: (annotation_argument_list) @n2 (#eq? @n2 "(value = \"/permissions/from-token\")")) @target)
      type: (generic_type) @target
      parameters: (formal_parameters) @target)))
```

Dos valores entran como **parte de la identidad del nodo** en vez de como contenido capturado:

- **La ruta del método**, en un `#eq?` sobre los argumentos del `@GetMapping`.
- **El tipo de retorno**, en el *kind* del nodo: `type: (generic_type)`. `List<PublicAuthorityDto>` es un `generic_type` y `PublicAuthorityDto` pelado es un `type_identifier`, así que cambiar la forma del tipo cambia la gramática del nodo y la query deja de matchear.

Cambiarlos no altera un fragmento: lo desaparece.

## La asimetría lo confirma

La anotación de clase entra con `#eq?` **sólo sobre el nombre** —`RequestMapping`— y sus argumentos quedan como contenido. Por eso cambiar la ruta de clase da `ALTERED` y cambiar la del método da `UNRESOLVED`. **Son el mismo cambio, la ruta compuesta, y se reportan como dos cosas distintas.**

## Por qué importa ahora y no después

Es la salida que un equipo de afuera lee primero. `UNRESOLVED` le dice al consumidor *"tu vínculo se rompió, repuntalo"* cuando lo que pasó es *"el proveedor te cambió la API"* — que es exactamente el mensaje que [`l`](l.user-story.md) existe para entregar, y el criterio de terminado de la épica.

No es un falso negativo: el drift **se detecta**, y ahí está la diferencia con [`10`](10.task.md). Lo que está mal es el diagnóstico.
