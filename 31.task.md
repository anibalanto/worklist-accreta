# Que lattice consuma `bilspd` en vez de invocar el CLI

El proveedor `bilink` de lattice arma una línea de comando y parsea la salida:

```rust
let args = vec!["graph", ".", "--format", "json"];
let out = Command::new(&self.binary).args(&args).current_dir(scope).output()?;
```

Un proceso por consulta, y un contrato que es *"un JSON sin esquema"*. Con [`30`](30.task.md) hay un daemon que contesta lo mismo por JSON-RPC, con el método declarado — y lattice pasa a tener **un solo patrón de proveedor**: `lspd` y `bilspd` por el mismo carril.

Es el tercer paso, y el último: [`1z`](1z.task.md) → [`30`](30.task.md) → ésta.

## Lo que cambia, y lo que no

**No cambia qué devuelve.** El payload es el mismo que el pipe ya emite y que este proveedor ya parsea; lo que cambia es que deja de ser un acuerdo de hecho.

**No cambia la arquitectura de proveedores.** El [`Provider`](../../subsystems/lattice/concepts/provider.md) ya está hecho para procesos: `available()` con tres estados y `edges_from()` para expandir bajo demanda existen porque el proveedor puede no estar o estar indexando. Hoy el proveedor `bilink` no puede usar bien `available()` —un `Command::new` está o no está, no hay `Degraded`—; con un daemon, sí.

**Sí cambia quién lo arranca.** Lattice ya tiene la política para `lspd`: *"si el daemon no responde, lo arranca"*. Es la misma para `bilspd`, y conviene que sea literalmente la misma y no una segunda copia.

## Por qué lattice no linkea la api

Es lo que decidió [`2z`](2z.task.md): linkear `bilinker::api` metería una flecha `lattice → bilinker` en el grafo de crates que hoy no existe. [`lspd/overview.md`](../../subsystems/lspd/overview.md) dibuja a lattice y bilinker apuntando los dos hacia adentro del daemon — *"ningún ciclo, ninguna inversión, y ningún compositor"*.

## Lo que destraba

**[Impact](../../subsystems/impact/overview.md).** Su blast radius es una sola consulta que une las tres clases de arista:

```
lattice graph <F> --up --via bilink,governs,call --format json
```

Con el proveedor `bilink` caído esa consulta devuelve la mitad, y impact no puede existir. Su spec además le prohíbe la salida de emergencia: *"Impact no recorre cadenas ni lee `.bilink`"*.

## Y no reemplaza a [`2x`](2x.task.md)

Mientras el pipe exista tiene que no mentir: `--format json` que no imprime nada es un bug igual, y `2x` es barato. Ésta lo vuelve innecesario, no correcto.

## Qué toca
