# Integración real con `acli`: crear o encontrar el issue, idempotente

La única pieza que habla con Jira de verdad. Recibe un ítem sin clave y un tipo (`Task`, `Historia`, `Epic` — mapeo a definir) y devuelve una clave real, creando el issue si no existe.

## Buscar antes de crear

Si el hook crea el issue y falla antes de commitear el `git mv` de [`52`](52.task.md), un reintento no puede duplicar. La defensa es buscar por título antes de crear — y el modo de falla conocido no es *olvidarse* de buscar, es que **la búsqueda falle en silencio**: en `bmad-issue-tracking` una comilla sin escapar en un título rompía el JQL, la búsqueda devolvía vacío, y el reintento duplicaba. Escapar el título antes de interpolarlo en cualquier búsqueda no es opcional.

## No corre contra `ACC` sin permiso

Se prueba contra un board de prueba, o con `--dry-run` que imprime qué crearía sin llamar a `acli`. El primer test contra el board real de accreta lo confirma quien lee esto, no el código solo.

## No manda el cuerpo del ítem como descripción

`acli jira workitem create --description-file` acepta texto plano o ADF, **nunca Markdown crudo** — verificado en `bmad-issue-tracking`, donde una descripción con formato terminaba como un único párrafo con los `**`/backticks sin interpretar. El cuerpo de un ítem del worklist tiene tablas, listas y blockquotes: mandarlo tal cual repetiría ese defecto.

**La salida es no mandarlo.** Git es la fuente de verdad en este diseño, no Jira — el issue es un puntero con id y estado, no un espejo del contenido. `--description` lleva **una línea plana**, siempre presente y nunca vacía —por si el proyecto exige el campo—: `Fuente: <ruta del ítem en el repo>`. Una línea sin formato es ADF válido sin convertir nada.

## Cuándo está hecha

- Test con un board de prueba: crear un issue nuevo, buscarlo de vuelta por título, confirmar que no se duplica. **Pendiente — necesita tocar Jira de verdad.**
- Test: un título con comillas o caracteres que rompen JQL sin escapar — la búsqueda sigue encontrando el issue. ✔ (como test puro de escapado, sin `acli`: `escapa_comillas_y_backslash`, `un_titulo_con_comillas_no_rompe_el_jql_generado`)
- Test: la descripción enviada es siempre la línea `Fuente: …`, nunca el cuerpo del ítem. ✔
- Un `--dry-run` que no llama a `acli` y muestra qué haría. ✔ (`dry_run_no_llama_a_acli`, y verificado a mano)

## Cómo se hizo

`Creator` (trait) + `AcliCreator` (real, `acli jira workitem search`/`create`) + `worklist create-or-find` en el CLI. Todo lo que se puede probar sin Jira está probado: 3 tests nuevos, puros, y dos bilinks (`escape_jql` y el comportamiento del comando), `all clean`.

**Lo único que falta es el test que exige un board real** — crear, buscar de vuelta, confirmar que no duplica. No corre sin permiso explícito, y `ACC` es el único board al que hay acceso hoy: no hay uno de prueba provisionado. Queda `in-progress` hasta que se decida si se usa `ACC` con un issue de prueba controlado, o se provisiona otro proyecto.
