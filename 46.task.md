# Poner a salvo los backups del corte y decidirles un hogar

Los 165 vecindarios que [`43`](43.user-story.md) restituye viven en los `.bilink-formato-3` de cada capa, y **eso no está versionado en ningún lado**:

```
$ cd ~/Workspace/hsi
$ git ls-files .bilink-formato-3        → 0
$ git check-ignore -v .bilink-formato-3 → .git/info/exclude:12:.bilink-formato-*
$ git ls-tree -r <ref> | grep -c formato → 0
```

Ni en la rama, ni en la ref, excluidos por el glob que puso [`3s`](3s.task.md). **Existen como archivos sueltos en un clon local y nada más**, así que reclonar o limpiar un árbol los borra — no hace falta que nadie cierre [`1x`](1x.task.md).

## Hecho el 2026-09-03: la copia existe

```
/home/anibal/Workspace/bilink-n1-backup-2026-09-03.tar.gz   144K
```

Las ocho capas, **excluyendo** el clon del proveedor de cada consumidor —`retinar` y `filasvirtuales` arrastraban 37 MB cada uno de `hsi/`, que se re-fetchea— y excluyendo `cache/` e `index/`, que son derivados. Verificado: **165 archivos con `n` adquirido adentro**, que es el número exacto que hay que restituir.

Es una copia de seguridad, no un hogar: está fuera de git.

## Lo que falta decidir

**Dónde vive hasta que [`4a`](4a.task.md) restituya.** Tres opciones, y la elección es del dueño del repo:

| | A favor | En contra |
|---|---|---|
| queda como tarball fuera de git | no ensucia ningún repo; ya está hecho | sigue sin versionar: una máquina, una copia |
| commiteado en accreta bajo `recovery/` | versionado y compartido; se borra al cerrar `43` | datos operativos en un repo de specs |
| commiteado en cada capa | viaja con lo que describe | el glob del exclude lo tapa; habría que exceptuarlo |

**Y cuándo se puede borrar**: cuando `4a` haya restituido y las capas verifiquen. Eso es lo que le falta a `1x` además de un dueño — *"un backup que nadie borra no es una política de retención, es un accidente que a veces sale bien"*.

## Qué toca

Nada de spec ni de código si queda como tarball. Si se elige un hogar en git, toca [`concepts/migration.md`](../../subsystems/bilinker/concepts/migration.md) o [`commands/migrate.md`](../../subsystems/bilinker/commands/migrate.md) — la retención del backup del corte, que es lo que [`1x`](1x.task.md) reclama.
