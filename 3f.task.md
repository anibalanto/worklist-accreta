# Error de flag: con `--from-repo`, `--as.N` y `--name.N` no numeran el mismo tip

`chain new --from-repo <alias>:<uuid>` toma **un solo** `--tip`, el local: el otro extremo lo aporta el flag. Pero los dos flags que van por tip no coinciden en qué número es ese tip único:

| flag | a qué extremo llega |
|---|---|
| `--as.0` | **el tip local** — es el que se le pasa a `plan_tip` |
| `--name.0` | **el endpoint `repo`**, que es el que queda en la posición 0 |
| `--name.1` | el tip local |
| `--as.1` | a ningún lado: se parsea, se valida el nombre, y se descarta |

O sea que para el mismo extremo hay que escribir `--as.0` y `--name.1`. Y `--as.1` con un generador válido no hace nada ni lo dice — con uno inválido sí falla, porque `generator_named` corre antes de la rama que lo ignora, lo que hace la inconsistencia todavía más difícil de leer.

## De dónde sale

El endpoint `repo` se arma **después** de resolver el tip local, y se empuja **antes**:

```rust
let plan = plan_tip(&root, &tip[0], modes[0].as_deref())?;   // --as.0 → el local
…
if let Some(r) = remote { tips.push(r); }                    // el repo queda en 0
for plan in &plans { tips.push((plan.layer_fs.clone(), plan.write()?)); }
```

`--as` numera **los `--tip` que se escribieron** y `--name` numera **los endpoints que quedan**. Con dos `--tip` las dos numeraciones coinciden y nadie se entera; con `--from-repo` se separan.

## Medido

**El 2026-09-02**, al escribir [`3c`](3c.task.md). El campo `as` que ese ítem agrega hereda el problema: hubo que acomodarlo a mano a la posición donde efectivamente cae el tip, y el comentario que explica por qué es más largo que el código.

## Qué hace falta decidir

**Cuál de las dos numeraciones es la buena.** No es obvio:

| | a favor |
|---|---|
| numerar los `--tip` | es lo que la persona escribió, y con `--from-repo` escribe uno solo — pedirle que lo llame `1` porque hay un `0` que no tipeó es pedirle que sepa cómo se arma el archivo |
| numerar los endpoints | es lo que queda escrito, y es lo que `bilinker get <uuid>.<N>` va a pedir después |

La segunda tiene la ventaja de que **el número es el mismo en toda la vida del bilink**. La primera, que el flag habla de lo que se está escribiendo y no de lo que quedará.

Y hay una tercera salida que no elige: **con `--from-repo` el sufijo no se pide**, porque hay un solo tip que numerar. `--as` y `--name` a secas, y `--as.N`/`--name.N` sólo cuando hay dos `--tip`. Que lo inválido no se pueda escribir es mejor que documentar cuál de los dos números vale.
