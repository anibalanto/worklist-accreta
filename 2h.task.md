# Error de declaración: `lspd` y `worklist-accreta` no se pueden traer con `stratum pull`

Una capa con repo propio se declara en `.stratum/.<nombre>.toml`, y eso es lo único que `stratum pull` lee:

```toml
remote = "git@github.com:anibalanto/bilinker.git"
branch = "main"
```

**Faltan dos**, las dos creadas en este sprint:

| Capa | Declaración | Estado |
|---|---|---|
| `subsystems/bilinker>impl` | `.impl.toml` | está |
| `subsystems/lattice>impl` | `.impl.toml` | está |
| `subsystems/stratum>impl` | `.impl.toml` | está |
| `subsystems/impact>impl` | — | **falta, y el repo tampoco existe** |
| `subsystems/lspd>impl` | — | **falta** — [`29`](29.task.md) |
| `*>worklist-accreta` | — | **falta** — [`2g`](2g.task.md) |

## Por qué importa más que un archivo de dos líneas

**`AGENTS.md` ya afirma que se puede**: *"Un clon de accreta no la trae: `stratum pull` sí."* Hoy eso es falso, y es la clase de afirmación que alguien descubre rota justo cuando la necesita — clonando por primera vez.

Y es peor que un link roto: un clon fresco no tiene la capa **ni forma de saber de dónde sacarla**. El directorio simplemente no está.

## Qué hay que hacer

`stratum add <nombre> --remote <url>` escribe la declaración. Para las dos que faltan y tienen repo. Para `impact`, que no tiene repo publicado, hay que **anotarlo, no inventarle un remote**.

## Cuándo está hecha

- `stratum pull` desde un clon fresco de accreta trae `lspd>impl` y `worklist-accreta`.
- Lo que `AGENTS.md` afirma es cierto.
- El caso de `impact` está anotado y no disimulado con una declaración que apunta a un repo que no existe.

## Lo que no entra

**Publicar el repo de impact.** Es una acción de afuera, como fue la de [`2f`](2f.task.md).
