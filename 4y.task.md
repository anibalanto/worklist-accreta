# Un link de un ítem a una spec es una cita de un instante, y tiene que pinear el commit

408 links de un ítem del worklist hacia `../../subsystems/…` son un path relativo sin versión. Cada uno es en realidad una cita de **cómo estaba la spec en el momento de escribirla** — tanto el que dice qué se va a tocar (74, en `## Qué toca`) como el que dice qué ya se decidió (~334, citas de fundamento). Las dos son lecturas de un instante y no hay motivo para tratarlas distinto.

## La forma

Una URL de GitHub pineada a un commit, resuelta con el mismo mecanismo que ya se usó para subir ítems a Jira — cruzando `.stratum/.<capa>.toml` cuando la spec vive en otro repo:

```
https://github.com/anibalanto/bilinker/blob/<sha>/concepts/cache.md
```

**Qué commit pinear:**

| Caso | Commit |
|---|---|
| el link está en `## Qué toca`, y la tarea modifica esa spec | el **previo** a la edición que la tarea hace |
| cita de fundamento | el que era `HEAD` de accreta cuando se escribió la cita |

Para lo nuevo, el segundo caso es exacto: es simplemente `HEAD` en el momento de escribir. Para las 408 ya escritas, no hay un registro de qué commit era `HEAD` cuando se tecleó cada una — se aproxima por el commit de accreta más cercano en el tiempo al `updated_at` del ítem que la contiene, y **queda marcado como aproximado**, no como exacto.

## Por qué, y qué no reemplaza

52 de los 408 cruzan a una capa de implementación gitignoreada — el mismo cruce que apareció al preparar la subida a Jira, y por el mismo motivo: un path relativo finge un solo árbol donde hay dos repos.

**Y no reemplaza al bilink.** Un permalink no deriva nunca — es la virtud y el límite: congela lo que el ítem encontró, que es lo correcto para un registro histórico, pero por eso mismo no puede reportar cuando la spec cambia. Eso lo sigue haciendo el endpoint `issue` cuando exista del lado del ítem — que es otro trabajo, no éste.

## Qué toca

- Los 128 ítems que llevan al menos uno de los 408 links.
- Un script de conversión: resuelve la capa (propia o vecina vía `.stratum/.*.toml`), busca el commit por fecha para las citas ya escritas, reescribe a URL pineada.

## Cuándo está hecha

Ningún ítem de `worklist-accreta` tiene un link `](../../subsystems/…)`. Todo link hacia una spec es una URL con un SHA de commit.

## Lo que queda por decidir

**Qué pasa cuando la aproximación por fecha no alcanza** — un ítem editado muchas veces, cuya cita se agregó en una edición intermedia sin fecha propia. Ahí `updated_at` del ítem no distingue cuál edición trajo esa línea en particular.
