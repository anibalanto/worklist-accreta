# Capturar un directorio, que hoy no se puede y hace falta para vigilar `docs/` entero

Un [capture](../../subsystems/bilinker/concepts/capture.md) nombra **un nodo del AST**, o el archivo entero cuando no lleva query. No hay forma de nombrar un directorio, así que *"vigilar la carpeta `docs`"* no se puede escribir.

**Y `path docs` no es eso.** El prefijo `path` es un stratum-path hacia una **capa vecina**, y el `accepted` de un endpoint `path` lleva una copia opaca del `accepted` del vecino. Usarlo para nombrar una carpeta le da dos significados al mismo prefijo, que es justo lo que la grilla de tipos existe para evitar.

## Por qué es un concepto y no un detalle

Un directorio no tiene texto: tiene un conjunto de archivos que cambia. Hashearlo pide decidir, y cada decisión tiene una salida defendible y una tentadora:

| | La pregunta |
|---|---|
| **orden** | los archivos se pliegan en algún orden, y tiene que ser por identidad y no por contenido — la misma razón por la que el vecindario ordena por id de capture |
| **recursión** | los subdirectorios entran o no, y si entran, hasta dónde |
| **ignores** | `.gitignore` gobierna, o hay uno propio, o entra todo lo trackeado |
| **un archivo nuevo** | entra al conjunto y mueve el hash — que para vigilar es lo correcto y para un fragmento sería ruido |
| **`hash_ast`** | no existe: un directorio no tiene gramática, así que todo cambio es real y `RESTYLED` no aplica |

Ninguna es difícil sola. Juntas son una spec.

## Salió de [`4o`](4o.user-story.md), y por eso está afuera

Vigilar **un archivo** ya se puede —un capture sin query es el archivo completo—, así que la US de roles y watchers sale entera sin esto. Pegárselo la haría depender de un concepto nuevo y probablemente la sacaría de un sprint.

Vuelve cuando alguien quiera vigilar una carpeta y no un archivo.
